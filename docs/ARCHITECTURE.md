# 🏗️ سیم‌کشی نسخه وب‌سایت — ابزار یدکی (abzaryadaki.com)

> مطابق قانون ۶ و ۸: سیم‌کشی قسمت‌های مختلف همیشه مستند می‌ماند؛ لایه‌بندی اصولی است.
> این سند مالکیت نسخه **وب‌سایت** است. پایه‌ی اپلیکیشن موبایل طبق دستور ۱۵ در همین ریپو ولی با تفکیک کامل کد قرار گرفت (بخش ۸) — با نسخه وب مخلوط نمی‌شود (قانون ۱).

## ۱. لایه‌ها (Layering)

```
┌─────────────────────────────────────────────────────┐
│ L1  ورودی برنامه        src/app/layout.tsx / page.tsx │  فقط فونت، متا، رندر SiteApp
├─────────────────────────────────────────────────────┤
│ L2  طراحی              src/app/globals.css           │  توکن‌های رنگ/تایپ از فایل HTML مدیر
├─────────────────────────────────────────────────────┤
│ L3  وضعیت و مسیریابی   src/lib/shop-state.ts         │  ۵ استور zustand + روتر hash
├─────────────────────────────────────────────────────┤
│ L4  داده نمایشی        src/data/store.ts             │  محصولات/سفارش‌ها/کوپن/... فارسی
├─────────────────────────────────────────────────────┤
│ L5  قالب مشترک         src/components/site/chrome.tsx│  هدر/فوتر/جستجو/نوار اعلان
│                        cart-drawer.tsx / mobile-bar │
├─────────────────────────────────────────────────────┤
│ L6  صفحات مشتری        src/components/site/views/    │  ۲۱ نمای hash
├─────────────────────────────────────────────────────┤
│ L7  پنل ادمین          src/components/site/admin/    │  ورود + ۱۰ تب
└─────────────────────────────────────────────────────┘
```

قاعده: هر لایه فقط به لایه پایین‌تر وابسته است؛ صفحات (L6/L7) هرگز مستقیم به هم وصل نمی‌شوند و همه از L3 مسیریابی می‌گیرند.

## ۳. استورها (Zustand + persist)

| استور | کلید ذخیره | محتوا |
|-------|-----------|-------|
| `useRoute` | — (حافظه) | صفحه فعلی، pid، دسته، جستجو، مرتب‌سازی |
| `useCart` | `abzar-cart` (localStorage) | سبد خرید |
| `useData` | `abzar-data` | محصولات/سفارش‌ها/کوپن‌ها/نظرات/پیام‌ها/بنرها/آدرس‌ها/کاربران/تنظیمات (قابل ویرایش از ادمین) |
| `useAuth` | `abzar-user` | کاربر لاگین‌شده |
| `useWish` | `abzar-wish` | شناسه‌های علاقه‌مندی |
| `useAdmin` | `abzar-admin` (sessionStorage) | نشست ادمین (با گیت ورود) |
| `useUI` | — | کشوی سبد، شیت، توست |
| `useRV` | — | آخرین بازدیدها (مثل طراحی) |

همه استورهای persist بعد از mount با `rehydrateAll()` آب می‌شوند (جلوگیری از ناهماهنگی SSR).

## ۴. قالب مشترک (chrome.tsx)

- **AnnBar**: نوار اعلان بالای سایت.
- **Header**: لوگو، جستجو، منو، آیکون قلب → `#wishlist`، حساب (کاربر؟ `#account` : `#auth`)، سبد → کشو، کلید حالت تاریب، «پیگیری سفارش».
- **Footer**: لینک‌های `#account`، `#track`، `#wishlist`، `#faq`، `#terms`، `#returns`، `#privacy`، `#cookies`، `#refund`.
- **CartDrawer / MobileBar / Toast**: کشوی سبد، نوار پایین موبایل، توست سراسری (`useUI.say`).

## ۵. پنل ادمین (admin-app.tsx)

## ۷. چرخه سفارش (سیم‌کشی کامل)

`#shop`/`#p-{id}` → افزودن به سبد (`useCart`) → کشوی سبد → `#checkout` (آدرس/ارسال/پرداخت/کوپن) → ثبت سفارش (`useData.addOrder` + کد سفارش) → `#done` → پیگیری از `#track` (کد سفارش + موبایل) → تغییر وضعیت از ادمین (تب سفارش‌ها) → مشاهده در `#account` سفارش‌های من.

## ۸. اپلیکیشن موبایل (دستور ۱۵ — v0.4.0-web — تفکیک‌شده از وب)

گرافیک مرجع: `upload/ابزار یدکی _ اپلیکیشن.html` (پرت ۱:۱، بدون تغییر گرافیکی؛ نام کلاس‌ها فقط برای ایزولاسیون با پیشوند `m` و اسکوپ `#mapp`).

**لایه‌ها:**
```
src/mobile/app.css      ← CSS گرافیک (متغیرها + حالت تاریب خودکار)
src/mobile/icons.tsx    ← لوگو، ۶ آیکون دسته، آیکون‌های تب، واتساپ، AI
src/mobile/MobileApp.tsx← نماها + سیم‌کشی (تنها کامپوننت)
src/app/api/ai-chat     ← دستیار خرید (SDK فقط سرور)
```

**فعال‌سازی (نقطه اتصال واحد: `site-app.tsx`):**
- مسیرهای `#app*` روی هر نمایشگر → اپ (در دسکتاپ قاب ۴۳۰px وسط صفحه — خودِ طراحی)
- نمایشگر تلفن (≤۷۶۷px) → خودکار اپ، به‌جز `WEB_KEEP` (تسویه، انجام سفارش، ادمین، حساب، علاقه‌مندی، پیگیری، درباره، تماس، تخفیف‌ها، سوالات، قوانین، حریم، کوکی، بازگشت پول، رویه بازگشت، ورود) که نمای وب می‌مانند

**مسیرهای اپ:** `#app` خانه · `#app-cats` دسته‌ها · `#app-cart` سبد · `#app-me` حساب · `#app-p-{id}` محصول — روی موبایل معادل‌های وب هم نگاشت می‌شوند (`#home`، `#shop`، `#cats` → اپ؛ `#p-{id}` → محصول اپ؛ `#cart` → سبد اپ؛ نامعلوم → خانه اپ)

**استورهای مشترک (همان نمونه وب):** `useCart` (سبد یکسان بین وب و اپ — نشان‌ها هر دو سمت همگام است)، `useData` (محصولات/تنظیمات: ارسال رایگان ۳ میلیون، پست ۸۰ هزار)، `useWish`؛ خودرو و عبارت جستجوی اپ در حافظه نشست (مطابق طراحی، بدون کلید ذخیره‌سازی جدید)

**دستیار هوش مصنوعی:** `POST /api/ai-chat` — کاتالوگ واقعی از استور ادمین + پرامپت عین طراحی؛ پاسخ با نشانه `[[شناسه]]` → کارت محصول با دکمه افزودن؛ خطا → پیام fallback طراحی

**سیم‌کشی منوی حساب اپ:** سفارش‌های من → `#account` · علاقه‌مندی‌ها → `#wishlist` · پشتیبانی → `#contact` · درباره ما → `#about` (نمای وب روی موبایل)

## ۹. لایهٔ داده واقعی — پایگاه داده (دستور ۲۲ — فاز D1 انجام شد)

پایگاه دادهٔ واقعی (Supabase/PostgreSQL — پروژهٔ `wdbixiercvkshmamobro`) ساخته و امن شد؛ سند کامل: `docs/DATABASE.md`.

```
supabase/migrations/0001_initial_schema.sql ← ۱۲ جدول + نمایه‌ها + توابع امن + RLS (۲۷ سیاست)
supabase/migrations/0002_initial_seed.sql   ← دادهٔ اولیه = کپی عینِ مقادیر کد
```

- وضعیت: **ساخت و راستی‌آزمایی انجام شد؛ کد وب هنوز به آن وصل نشده** (فریز — تا تأیید سیم‌کشی فاز D2 توسط مدیر)
- L4 آینده: خواندن کاتالوگ/تنظیمات از Supabase با کلید عمومی anon + امنیت RLS؛ ثبت سفارش فقط با تابع `create_order` (قیمت‌گذاری سمت سرور — ضد دستکاری)؛ L4 فعلی (`src/data/store.ts`) تا آن زمان عیناً می‌ماند
- احرازهویت: Supabase Auth (OTP پیامکی) — رمز فقط با bcrypt هش می‌شود؛ هیچ ستون رمزی در دیتابیس نیست
- نقش ادمین: `profiles.role = 'admin'` از طریق `is_admin()` — اتصال پنل ادمین به دیتابیس = فاز D3
- فازها: D1 ✅ ساخت+امنیت · D2 🔲 سیم‌کشی وب (v1.1.0-web) · D3 🔲 پنل ادمین · D4 🔲 دستیار AI با کاتالوگ زنده
- توکن‌ها و کلیدها فقط محلی (`secrets/` خارج از ریپو + `.git/config`) — مصوبه ۵ و ۶؛ هرگز در گیت
