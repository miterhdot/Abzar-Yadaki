**وضعیت و نکتهٔ گذار:**
- راستی‌آزمایی زنده پس از ثبت cname: آدرس `daadv.github.io/abzaryadaki/` با **301** به `http://abzaryadaki.com/` ریدایرکت می‌شود (رفتار استاندارد گیت‌هاب پس از ثبت دامنه) — تا اعمال DNS، این ریدایرکت به میزبان قبلی (88.135.68.12) می‌رسد؛ به‌محض اعمال رکوردها، دامنهٔ رسمی نسخهٔ جدید (بیلد ریشه) را سرو می‌کند
- «Enforce HTTPS» پس از ثبت دامنه به‌صورت خودکار False شد — پس از اعمال DNS و صدور خودکار گواهی، فعال می‌شود
- DNS فعلی دامنه (پیش از اقدام مدیر): `@` و `www` هر دو → `88.135.68.12` (میزبان قبلی) — باید با رکوردهای Pages جایگزین شود

**رکوردهای DNS تحویل مدیر شد:** ۴ رکورد A برای `@` (185.199.108.153 / 185.199.109.153 / 185.199.110.153 / 185.199.111.153) + CNAME برای `www` → `daadv.github.io` (MX/TXT ایمیل دست‌نخورده)

**پیگیری (همان روز):** پنل DNS مدیر فقط ۴ ردیف دارد → نسخهٔ ۴ ردیفی تحویل شد: ۳ رکورد A برای `@` (185.199.108.153 / 185.199.109.153 / 185.199.110.153 — آی‌پی چهارم فقط ردیف یدکی گیت‌هاب است و حذفش بی‌اثر) + ۱ رکورد CNAME برای `www` → `daadv.github.io` — هم دامنهٔ اصلی و هم www پوشش داده می‌شود (www خودکار به آدرس اصلی ریدایرکت می‌شود)؛ گزینهٔ جایگزین: ۴×A بدون www (توصیهٔ کامل گیت‌هاب)؛ قبل از درج، رکوردهای قبلی (→ 88.135.68.12) حذف شوند

**پیگیری ۲ (همان روز — «نیم سرور بفرست»):** اسکرین‌شات مدیر از پنل میزبان‌فا نشان داد مقادیر رکوردها در بخش «NameServer» وارد شده‌اند → هشدار فوری: GitHub Pages نیم‌سرور ندارد؛ NameServer باید همان خوشهٔ `dns1–4.mizbanfadns.net` بماند (راستی‌آزمایی DNS) و مقادیر وارد‌شده پاک شود (اگر ذخیره شده → فوراً بازگردانی، وگرنه DNS دامنه از کار می‌افتد)؛ رکوردها فقط در بخش «مدیریت DNS» (زون‌ادیتور) پنل درج می‌شوند؛ متن آمادهٔ پشتیبانی میزبان‌فا + گزینهٔ سرویس DNS ایرانی جایگزین ارائه شد؛ تصویر مدیر (شامل اطلاعات شخصی) طبق مصوبه ۵ کامیت نشد — `.gitignore`: استثنای `upload/pasted_*`

**پیگیری ۳ (همان روز — پرسش مدیر: «این هاستی که گیت‌هاب میده چه امکاناتی داره و چرا ما باید ازش استفاده کنیم چه سرعتی و چه امتیازی داره»):** پاسخ مشاوره‌ای مستند ارائه شد (بدون تغییر کد): سقف‌های رسمی از مستندات گیت‌هاب (سایت ≤ ۱ گیگ، پهنای‌باند نرم ~۱۰۰ گیگ/ماه، سقف نرم ۱۰ بیلد/ساعت — با ورک‌فلو سفارشی ما اعمال نمی‌شود؛ فقط استاتیک) + بند قوانین گیت‌هاب دربارهٔ ممنوعیت میزبانی «کسب‌وکار آنلاین عمدتاً تراکنشی» (وضعیت فعلی بدون درگاه پرداخت مشکلی ندارد؛ با افزودن درگاه واقعی → مهاجرت). راستی‌آزمایی زنده: CDN = Fastly (هدر `x-fastly-request-id`)، HTTP/2 فعال، پاس ۲۰۰ از طریق IP گیت‌هاب با TTFB سرد ~۲۸۰ms و گرم ~۱۲ms، **حجم کل خروجی استاتیک = ۱٫۱ مگابایت** (~۰٫۱٪ سقف)، HTML خانه ~۲۵KB؛ گواهی SSL دامنهٔ رسمی هنوز صادر نشده (طبیعی پیش از DNS — صدور خودکار پس از اعمال)؛ DNS فعلی راستی‌آزمایی شد: دامنه هنوز روی 88.135.68.12 است. مزایا اعلام شد: رایگان، HTTPS خودکار، انتشار خودکار با هر پوش، بدون نگهداری سرور، نسخه‌بندی و بازگشت با گیت، بدون قفل (مهاجرت به هر میزبان آینده ممکن). ریسک‌ها شفاف اعلام شد: بدون بک‌اند (درگاه پرداخت فعلاً نمی‌شود)، بدون گره CDN در ایران (کندتر از هاست داخلی برای کاربر ایرانی)، نوسان احتمالی فیلترینگ (تست پس از DNS)، بدون SLA
