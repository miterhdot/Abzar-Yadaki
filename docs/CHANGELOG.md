## [فاز D3 — پنل ادمین روی دیتابیس + کوپن سمت سرور + اعلان زنده] — ۱۴۰۵/۰۸/۱۴ (دستور ۲۵)

**دستور مدیر:** «۲-۳-۴ را اولویت بده انجام بدیم» + ارائهٔ توکن‌های جدید — سهم سمت ما = فاز D3 (مصوبهٔ دائمی ۱۶)

**انجام شد:**
- **مایگریشن ۰۰۰۴ روی دیتابیس زنده اعمال شد** (بدون باز کردن هیچ دسترسی عمومی جدید): RPC امن `check_coupon` (اعتبارسنجی کوپن برای تسویه — کد ناموجود و نامعتبر پاسخ یکسان می‌دهند، ضد شناسایی) + ستون `used_count` و تریگر شمارش استفادهٔ کوپن + Realtime روی `orders` و `contact_messages` برای اعلان زنده (RLS حکم می‌کند — فقط ادمین رخداد را می‌گیرد)
- **ورود واقعی ادمین:** ایمیل + رمز (Supabase Auth) + بررسی نقش `admin` در پروفایل؛ بازیابی نشست پس از رفرش؛ در نبود متغیرهای دیتابیس، همان ورود نمایشی مصوب (admin/admin123 — مصوبه ۱۰)
- **هر ۱۰ تب پنل به دیتابیس واقعی وصل شد** (همه با سیاست‌های موجود RLS — هیچ سیاست جدیدی باز نشد): داشبورد با آمار زندهٔ واقعی (جای اعداد جعلی: ۱۲٬۴۵۰٬۰۰۰ تومان، ۱۲۴۸ مشتری، ۳۹۴۰ بازدید و نمودارهای ثابت)، محصولات CRUD با دسته‌های واقعی دیتابیس، سفارش‌ها با قیمت لحظهٔ ثبت و تغییر وضعیت خوش‌بینانه، مشتریان از تجمیع سفارش‌ها + پروفایل‌ها، صف نظرات، کوپن‌ها با ستون «استفاده»، بنرها، صندوق پیام‌ها، گزارش‌های واقعی، تنظیمات روی دیتابیس
- **اعلان زندهٔ سفارش/پیام جدید** در پنل (Realtime) + بارگذاری مجدد خودکار
- **کاتالوگ واقعی برای بازدیدکننده:** محصولات/بنرهای فعال/تنظیمات/نظرات تأییدشده در بوت سایت از دیتابیس بارگذاری می‌شود (fail-soft) → تغییرات ادمین واقعاً در سایت ظاهر می‌شود؛ کاتالوگ خالی هرگز رخ نمی‌دهد (گارد عمدی)
- **کوپن در تسویه سمت سرور شد:** قبلاً کوپن از کلاینت خوانده می‌شد که در واقعیت همیشه رد می‌شد (RLS) — الان با RPC امن `check_coupon` اعتبارسنجی و مبلغ واقعی نمایش داده می‌شود
- **تست امنیتی زندهٔ ۴۲/۴۲ سبز** با حساب ادمین موقتی (ساخته و پس از تست کامل حذف شد + cascade پروفایل): ۲۰+ تست مثبت ادمین (شامل تغییر وضعیت سفارش واقعی و بازگردانی، CRUD محصول/کوپن، تنظیمات و بازگردانی)، ۱۲ تست منفی anon (همهٔ خواندنی‌های حساس = خالی، PATCH سفارش بی‌اثر، کوپن ناموجود بدون افشا)، تریگر used_count (۰→۱) و پاک‌سازی کامل آثار تست
- `bun run lint` + `bunx tsc --noEmit` (به‌جز ۳ خطای قبلی خارج از دامنه) + `bun run build` بدون خطا؛ دو خطای مسیر تست در `DATABASE.md` بخش ۸ ثبت شد (قانون ۷)
- موبایل (`src/mobile/`) طبق قانون ۱ دست‌نخورده؛ بدون تگ نسخه (تگ‌ها منتظر v1.0.0-web — مصوبه ۱۵)

**فایل‌ها:** `supabase/migrations/0004_admin_backend.sql` (جدید)، `src/lib/supabase.ts` (لایهٔ ادمین)، `src/components/site/admin/admin-app.tsx` (سیم‌کشی کامل)، `src/components/site/views/checkout.tsx` (کوپن سمت سرور)، `src/components/site/site-app.tsx` (هیدرات کاتالوگ)، `docs/{DATABASE,CHANGELOG,COMMANDS}.md`

**ورودی بعدی از مدیر:** ایمیل مدیر برای ساخت حساب ادمین واقعی (تنها ورودی باقی‌ماندهٔ D3 — حساب موقت تست حذف شده است)

## [پیگیری DNS — تأیید نهایی اتصال دامنه به Vercel] — ۱۴۰۵/۰۸/۱۲ (پیگیری دستور ۲۴)

- **راستی‌آزمایی زندهٔ مجدد (بدون هیچ تغییری از سمت ما):** تغییر نیم‌سرور **عملاً اعمال و سراسری شده است** — NS از سه مسیر مستقل (سیستم، 8.8.8.8، 1.1.1.1) = `ns1.vercel-dns.com` / `ns2.vercel-dns.com`؛ زون اقتدارگرای Vercel: apex A → `64.29.17.1` / `64.29.17.65` و www A → `216.198.79.65` / `64.29.17.65`؛ API ورسل: هر دو دامنه `verified: true` و بدون خطای پیکربندی؛ HTTP: apex `308` → www و www `200` با گواهی معتبر و محتوای واقعی (عنوان صحیح). **اتصال دامنه کامل و پایدار است — مسیر «الف» گزارش دستور ۲۴ در سطح زون عملی شد.** کش قدیمی `88.135.68.12` منقضی شده و رفتار مخلوط برطرف است.
- **⚠️ هشدار ایمیل:** زون جدید Vercel هیچ رکورد MX/TXT ندارد و نیم‌سرورهای میزبان‌فا دیگر برای دامنه پاسخ نمی‌دهند → اگر سرویس ایمیل روی `@abzaryadaki.com` وجود دارد، دریافت ایمیل قطع شده است؛ رکوردهای MX/TXT باید در پنل DNS Vercel بازسازی شود (مقادیر قبلی فقط از پنل/همان تیکت میزبان‌فا قابل استخراج است).
- کد فریز — هیچ تغییری در کد یا DNS انجام نشد؛ ثبت: `docs/COMMANDS.md` ردیف ۲۴ + متن آمادهٔ پاسخ به تیکت تحویل مدیر شد.
